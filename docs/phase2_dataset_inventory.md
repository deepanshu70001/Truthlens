## 5. Perceptual Hash Analysis (dHash & pHash)

Perceptual hashing was performed using 64-bit Difference Hashing (`dhash`) and 64-bit Discrete Cosine Transform Hashing (`phash`). Pairwise Hamming distances were evaluated across all $\frac{266 \times 265}{2} = 35,245$ possible image pairs.

### Summary of Pairwise Distances

| Metric | Distance = 0 (Exact Perceptual Match) | Distance $\le 2$ (Near Duplicate) | Distance $\le 5$ (Candidate Near Duplicate) |
| :--- | :---: | :---: | :---: |
| **Difference Hash (dHash)** | 13,742 pairs | 13,877 pairs | 16,248 pairs |
| **Perceptual Hash (pHash)** | 13,753 pairs | 13,817 pairs | 13,903 pairs |

### The Dominant Dummy Cluster (dHash `0000000000000000`)

* **165 of the 266 images** produce the exact same dHash (`0000000000000000`) and pHash (`8000000000000000`).
* Within this single cluster alone, there are $\frac{165 \times 164}{2} = \mathbf{13,530\text{ zero-distance pairs}}$, representing **98.4% of all zero-distance pairs in the repository**.
* **Root Cause:** Automated test fixture generators created flat, solid-color dummy images (primarily 100x100 solid fill) to test image storage pipelines without requiring natural images.

### Cross-Scale and Derivative Near-Duplicates
Outside the dummy cluster, perceptual hashing successfully grouped multi-resolution versions of the same images:
* `data/originals` vs. `data/processed/*_large.jpg` (dHash distance 0–1)
* `data/originals` vs. `data/processed/*_medium.jpg` (dHash distance 0–2)
* `data/originals` vs. `data/thumbnails/*_thumb.jpg` (dHash distance 0–3)

> [!NOTE]
> Perceptual hash distance $\le 2$ indicates identical visual content across rescaled or compressed variants. However, per project research guidelines, perceptual hash equality must never be used to automatically delete images or infer authenticity labels.

### What is Missing
To conduct valid empirical evaluations, model calibration, or benchmark reporting, the following components are missing:

1. **Curated Evaluation Benchmark Corpus:**
   * No standard synthetic/real image dataset (e.g., CIFAKE held-out test split, GenImage, FakeNewsNet, IFND, or RRDataset) is installed in the repository.
   * No balance between real photographic imagery and diverse AI generator outputs (e.g., Midjourney, Stable Diffusion, DALL-E, Flux, GANs).
2. **Ground-Truth Labels & Provenance Documentation:**
   * Zero images possess human-adjudicated labels with documented provenance.
   * No acquisition timestamps or source platform URLs exist.
3. **Legal & Licensing Documentation:**
   * No documented reuse rights, open licenses (e.g., CC BY, Apache-2.0, MIT), or privacy consent records exist for the files in `data/originals` or `test_data/originals`.
4. **Data Isolation & Leakage Prevention:**
   * Because 73.3% of the images are redundant exact duplicates and multi-scale copies, any random partitioning without group-level hashing would cause severe train-test leakage. Group-level splits based on perceptual hashing or source IDs must be established when a real dataset is introduced.
